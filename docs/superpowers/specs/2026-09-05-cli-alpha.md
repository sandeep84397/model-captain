# ModelCaddie CLI alpha

## Approved direction

Build a public GitHub repository and installable provider-neutral CLI. Users evaluate available model configurations and obtain evidence-based model, native-setting, responsibility and prompt guidance. The initial implementation is deliberately a small, honest evaluation slice of the broader product.

## Initial scope

Python >=3.11, standard-library runtime, setuptools packaging. Package `model_caddie`; command `model-caddie`. All state stays local. OpenAI Responses and Anthropic Messages adapters sit behind a provider protocol with injectable HTTP transport. Explicit JSON candidate configurations identify provider, exact model ID, optional native effort, output cap and optional dated input/output prices. Native efforts are not mapped across providers. No hardcoded production ranking.

Commands:

- `model-caddie init`: write an ignored starter JSON config, refuse overwrite. Default demo plus example live candidates users can edit. No credentials written.
- `model-caddie evaluate --provider demo|openai|anthropic|all --config model-caddie.json --output results/run.json --repetitions 1 --max-requests 12`: run a bundled programming microtask suite or `--suite FILE`. Live providers require `--live` and their environment keys. `--provider all` means live providers only. Preflight entire run before requests; refuse if planned calls exceed the cap rather than silently truncate. No automatic retries. Fixed timeout. Store all failures as failed attempts. An interrupted/error run must not appear complete.
- `model-caddie report --input results/run.json`: show readable task/category measurements and unknown cost explicitly.
- `model-caddie recommend --input results/run.json --category debugging --task TEXT`: no network; select a provisional configuration from comparable complete real results for that category, with evidence and a reusable task prompt. Below 3 unique tasks or quality threshold 0.8: insufficient evidence. Repetitions do not count as unique tasks. Demo always yields demonstration-only status, never real model advice. Unknown categories cannot silently route elsewhere.
- `model-caddie export --input results/run.json --format agents-md|claude-md --output FILE`: network-free scoped guidance plus limitations. Refuse overwrite unless explicit `--force`. Exporting demo produces a clearly marked demonstration document without deployment routing.
- `python -m model_caddie` must expose the same CLI.

Task suites are versioned JSON documents with unique task IDs, category, prompt, grader (`exact` or `json_subset`) and expected value. Reference answers never enter provider prompts. Ship at least 3 distinct tasks per supported category (debugging, code-review, testing), designed as objective reasoning microtasks, not broad competence certificates. Grading reads output as data and never executes generated code. Strict JSON types (true is not 1); malformed/refusal/truncated responses fail rather than receiving passing scores.

Reports record schema version, run ID/time, suite content hash, exact candidate configuration, repetitions, planned calls, completion status, mode (synthetic vs live), per-task/repetition results, errors, latency, provider-reported token usage, requested and returned model identifiers and pricing snapshot where supplied. Unknown usage stays unknown. Reasoning tokens already included in output totals are not added twice. Missing/ambiguous costs (including errors with unknown billing) remain unknown. Prices are user-supplied estimates, not live billing claims.

Recommendations compare only exact task/repetition coverage within a single suite/run, never disjoint workloads. Eligibility includes complete coverage and task quality >=0.8; ties may yield a shortlist. Rank eligible candidates by known estimated cost per accepted task only when cost is known for all compared attempts/candidates; otherwise explicitly use measured latency, without cost-saving claims. Always label the small-suite output provisional, show unique task/attempt counts and provenance, and avoid statistical confidence claims. Input reports require structural/value validation; do not trust an edited summary over attempt records.

## Security and integrity

Live requests go only to fixed official HTTPS endpoints. Do not follow redirects with credentials. Secrets are read from environment (`OPENAI_API_KEY`, `ANTHROPIC_API_KEY`) at runtime and never written to configuration, reports or error text. Do not persist raw provider error bodies or headers. No arbitrary endpoint, shell execution, repository uploads, or generated-code execution. Model output is untrusted data; exported instructions must come from controlled templates, not generated response text.

Request count and output-token limits are guardrails, not a hard dollar cap. Do not silently retry. No real model calls or paid evaluation during development. Demo must work offline and be unmistakably synthetic. Reports may contain task/model output; generated state is gitignored.

## Deferred product work

Native Codex/Claude Code harnesses and repository execution; containerized patch grading; provider/model capability discovery; rigorously calibrated confidence; sealed holdout suites; cost-aware adaptive experiments; guaranteed monetary reservation; dashboard; automatic routing execution; provider-priced subscription usage. These are not represented as implemented or validated by the microtask alpha.

## Acceptance

## Preflight review refinements (binding)

- Validate finite numeric values and strict types. Bounds: 100 tasks per suite, 16 candidates, 10 repetitions, 16 KiB UTF-8 per prompt, 1 MiB combined prompts, 32768 output tokens per call, 1000 maximum request cap. IDs unique, nonempty; empty suite/config rejected. All preflight checks and all required keys are resolved before the first live request.
- Print candidate IDs/model/settings, exact planned calls, worst-case generated-token ceiling and `cost unknown` before live evaluation. Native effort values may be constrained to documented API-level values but per-model compatibility remains provider-validated. `ultra` is not an API effort value and is rejected clearly.
- `evaluate --output` refuses collisions without `--force`; reports written atomically. A handled interruption records an incomplete run or leaves no final report; it must not fabricate completion.
- A recommendation must reject incomplete/duplicate/missing attempts and unverified returned model IDs. Requested/returned model mismatch or mixed returned IDs excludes the candidate from routing advice (snapshot aliases may be configured explicitly as a future extension).
- When cost cannot compare all candidates, return an eligible shortlist unless there are at least 3 repetitions per task; with sufficient repeats, latency language is only `lowest observed median in this run`. Quality threshold remains mandatory; no claim of statistical superiority.
- Every export says guidance applies only to tested categories/tasks/configurations and does not grant autonomous responsibility or claim universal/provider-wide ranking.

Fresh installation exposes CLI; offline init/evaluate/report/recommend/export path works; network blocked by default; API request/response contracts tested through transport doubles; malformed configs/reports and unknown settings fail clearly; demo cannot generate real recommendations; all attempts and coverage reflected in recommendation; no source answers sent to provider; dependency-free runtime; CI executes tests and CLI smoke on Python 3.11-3.14. Public publication includes only intentional source/docs/tests, no credentials or local transcripts.
